E-commerce Payment Default Risk Model

A binary classification model that predicts whether an e-commerce order is high-risk (payment default), built using Python, exploratory data analysis, feature engineering, preprocessing, and multiple machine learning models.

Retailers and lenders lose money when they cannot identify which customers are likely to default on payment before an order is processed. I built a binary classification model to predict that risk, with a focus on improving the detection of the minority class using precision, recall, and F1-score rather than relying on accuracy alone.

Python Pandas Scikit-learn Feature Engineering Classification

How I built it

The dataset was a German-language e-commerce dataset containing approximately 30,000 transactions and 44 features. Before modeling, I performed extensive exploratory data analysis to understand feature distributions, identify missing values, detect class imbalance, and evaluate which variables carried predictive signal. This stage guided decisions about which features to keep, engineer, or remove before training any models.

I engineered several features, including customer age groups, time-of-day buckets, order-hour features, and a binary HAS_PREVIOUS_ORDER indicator derived from historical purchase data. Missing values were handled strategically rather than being removed, preserving information that proved highly predictive of default behavior. Identifier and sparse product-code columns were dropped to reduce noise and dimensionality.

The preprocessing pipeline was built using ColumnTransformer, applying OneHotEncoder to categorical variables and StandardScaler to numerical features for models that require feature scaling. The dataset was split using an 80/20 stratified train/test split to preserve the original class distribution during model evaluation.

Challenges & what I learned

The most significant challenge was severe class imbalance: only about 5.8% of transactions were labeled as high-risk. Baseline models achieved roughly 94% accuracy, but initially failed to identify many default cases. This reinforced that accuracy can be misleading in imbalanced classification problems and that recall and F1-score are often more meaningful business metrics.

I trained and compared Logistic Regression, Decision Tree, Random Forest, and Gradient Boosting models. I then applied hyperparameter tuning and evaluated SMOTE (Synthetic Minority Over-sampling Technique) to improve minority-class detection. Hyperparameter tuning increased the positive-class F1-score from 0.16 to 0.25 and improved recall from 0.18 to 0.32, while SMOTE dramatically increased recall to 0.69 at the cost of lower precision and overall accuracy.

What I learned

This project taught me how to build a complete machine learning pipeline: exploratory data analysis, feature engineering, missing-value strategy, one-hot encoding, standard scaling, model comparison, hyperparameter tuning, and class-imbalance handling. The biggest takeaway was that preprocessing and feature engineering often have a greater impact on model performance than simply choosing a more complex algorithm.
